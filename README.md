# gpt-image-2.5绘画

AstrBot 图片生成、编辑与异步视频插件，版本 `1.0.10`，要求 AstrBot `>=4.19`。适配 OneBot v11（`aiocqhttp`）和 QQ 官方机器人（`qq_official` / `qq_official_webhook`）。版本变化请参阅 `CHANGELOG.md`；在线 Web API 以部署后的 AstrBot Scalar 文档 `/scalar.html` 和 OpenAPI 描述 `/openapi.json` 为准。

## 版本与升级

- 当前版本：`1.0.10`
- 更新来源：固定为 `3121871622/gpthh`。通过主分支 `update-manifest.json` 比较版本与构建修订，再读取 `CHANGELOG.md`；同版本的新修订也会显示更新，当前构建为 `2026111001`。
- 版本格式：遵循 `MAJOR.MINOR.PATCH`；不兼容配置变更会在 `CHANGELOG.md` 的对应版本中单独标注。`1.0.9` 新增文/图生视频、交互式秒数输入、进度通知与任务轮询；`1.0.10` 将视频设置整理为独立「视频生成」页，并加入模型选择和静态资源版本标记。
- 页面升级：保存配置 → 点击顶部「检查更新」→「安装更新并重载」→ 等待成功 →「刷新设置页」。安装由 AstrBot 插件管理器执行；界面显示检查、安装、重载和验证的实际阶段，不以下载完成代替重载成功。
- 检查等待：显示旋转指示和已等待秒数，最长 20 秒；可点击「停止等待」，之后重新检查。系统开启减少动态效果时显示静态状态与秒数。停止检查不会取消已经提交的安装或重载任务。
- 单独重载：保存后可点击顶部「重载插件」，重新初始化本插件。保存配置接口只重读配置，不等同于插件重载。
- 首次接入：旧安装没有这些按钮时，先用 AstrBot 插件管理页更新本插件一次，或备份插件目录和配置后安装新的 `1.0.10` 包并重载，再重新打开设置页。包内不能多嵌套一层 `1.0.10/`。
- 维护保护：等待正在生成的图片、视频及秒数交互结束，或先取消交互；维护期间暂不接受新的生成任务。失败时按页面提示检查 AstrBot 日志，不会误报完成。宿主缺少所需管理接口时，使用 AstrBot 插件管理页。
- 后续发布：即使版本号不变，也应递增 `update-manifest.json` 的 `build`；升级版本时同步更新其中的 `version`。本地构建号来自随插件安装的文件，不从远程最新值冒充已安装版本。
- 页面刷新：升级并重载插件后重新打开可视化设置，确认出现「视频生成」分区。`1.0.10` 为页面静态资源附加版本标记，以区分不同版本的脚本与样式；这不改变 AstrBot 宿主的缓存策略。
- 配置迁移：保留已有 `suppliers`、`providers`、`channels`、`protocol_models`、菜单、预设和统计数据；升级后建议打开设置页点击一次「保存配置」。
- 发布包结构：解压后第一层应直接看到 `metadata.yaml`、`main.py`、`core/` 和 `pages/`；历史版本通过 Git tags 保存，`v1.0.9` 和 `v1.0.8` 保持不变；主分支仅保留当前项目文件。
- 升级后检查：先执行 `菜单`、`模型列表` 和 `运行统计`，再按需测试绘画、编辑、翻译模型和视觉模型。

## 安装与配置

1. 将插件放入 AstrBot 的 `data/plugins/astrbot_plugin_gpt_image/` 并重载；上传压缩包时，包内第一层应直接包含 `metadata.yaml`、`main.py`、`core/` 和 `pages/`。发布包使用版本号命名，例如 `1.0.10.zip`。
2. 打开插件设置，填写供应商名称、Base URL、API Key，选择该服务支持的协议及模型。编辑模型留空时沿用生成模型；模型默认名称不代表服务端一定支持。
3. 发送 `我的ID` 获取用户 ID，在设置中配置主人。群聊默认需要主人先发送 `开群` 或 `群开关 开`。
4. 发送 `绘画 一只猫`；发送 `菜单` 查看用法。

在「供应商与协议」勾选目标卡片的「设为此供应商」，再保存；数字名称如 `1`、`22` 按完整名称保存。切换后模型面板会显示对应供应商。聊天中已经设置的会话覆盖与机器人独立配置优先于全局默认；需要跟随全局配置时使用「重置设置」清除本会话覆盖，并检查机器人独立配置。

在「供应商与协议」的生成/编辑模型输入框填写模型 ID，停止输入约 0.7 秒后自动逐家查询；也可点击「检测供应商」刷新。精确命中的行可点「使用此供应商」，仅更改页面草稿，仍需保存。编辑模型留空时检查生成模型的同一 ID，但不据此宣称支持编辑。

检测仅查询目录，不会自动生成图片或消耗生成次数。目录出现该 ID 不代表实际生成一定可用；没有目录、分页不完整或请求失败会明确显示未确认。供应商凭据或地址改动须先保存，近期缓存结果不会冒充本次连通成功。点击「停止检测」停止页面等待和未发出的查询，已经发出的只读请求自行结束。图片真实生成仍使用原有聊天指令。

供应商保存地址和密钥，协议及模型另行选择；同一服务是否支持多个协议需由服务商确认。插件设置页位于 `pages/settings/`，插件目录名请保持 `astrbot_plugin_gpt_image`。

图片失败重试只使用本次选定的供应商，不会自动从供应商 A 切换到 B。视频可单独绑定供应商和该供应商支持的真实模型 ID；指定视频供应商后，不随图片通道切换，留空时才沿用当前会话供应商。

## 异步视频生成（自 1.0.9 起）

视频采用先输入描述、再选择秒数的两步交互：

1. 文生视频：发送 `文生视频 一只橘猫坐在窗台上，镜头缓慢推进`。
2. 图生视频：发送 `图生视频 让画面中的云缓慢移动` 并附带图片，或引用含图片的消息后发送该指令。`Images 数组视频` 模式支持有序多图（最多 10 张、每张 20 MiB、合计 100 MiB）；其他两种模式仍为单图，实际可用张数由供应商和模型决定。
3. 收到时长提示后，在同一聊天中回复 `10`、`10s` 或 `10秒`。本地接受 1–120 的整数秒数，最终以供应商和所选模型实际支持的时长为准，并不保证每个模型支持整个范围。默认等待输入 120 秒，超时后重新发送视频指令。

原有 `生成视频` / `视频生成` 别名继续可用。插件只提交一次任务，返回任务 ID 后在后台查询；取得成片后发送视频，平台发送失败时尝试返回可访问的视频链接。视频与图片使用独立模型和并发限额，群开关、黑名单、机器人实例过滤及冷却规则仍然生效。

打开可视化设置页的独立「视频生成」分区，集中配置视频模型、供应商和异步任务参数；无需再到「模型与尺寸」页面下方寻找。

- **视频模型**默认为空，可从供应商模型列表选择，也可手动填写供应商支持的完整模型名称。空模型仍可保存其他设置；发起视频任务时会提示到后台补充。供应商返回的模型目录仅用于选择，实际视频能力以其接口为准。
- 在「供应商」中配置 Base URL 和 API Key，再选择视频供应商；留空沿用当前会话解析出的供应商。发布内容不内置测试站地址、测试密钥或测试模型。
- `New API 异步视频`（默认 `legacy`）：`POST /v1/video/generations` 提交，`GET /v1/video/generations/{task_id}` 查询。支持 New API 外层 `data`、大写状态及内层上游结果，始终用网关任务 ID 查询。
- `Images 数组视频（单图/多图）`（`images`）：`POST /v1/videos` 发送 JSON，时长用整数 `duration`，参考图只放在有序 `images` 数组内；单图也是 1 项数组，不与旧单图字段混用。`GET /v1/videos/{id}` 查询并使用结果 URL。遇到“images 不能与旧版单图字段同时使用”时，在「视频生成 → 视频接口模式」选择此模式并保存。
- `OpenAI 兼容视频`（`openai`）：`POST /v1/videos` 提交，`GET /v1/videos/{id}` 查询；完成响应没有公开 URL 时，经认证下载 `/v1/videos/{id}/content` 后发送临时视频文件。
- 状态查询默认每 **5 秒**一次（2–60），聊天进度通知默认每 **10 秒**一次（5–60）。等待输入时长默认 **120 秒**（30–600），生成任务等待上限默认 **900 秒**（30–3600），视频最大并发默认 **2**（1–8）。指令别名可在「指令与菜单」中编辑。

进度优先使用上游返回的真实百分比；没有可用百分比时，显示明确标注的估算进度，从 1% 开始。**估算仅供参考，不代表剩余时间**。尚未取得视频结果时不会显示 100%；仅在取得成片后发送完成通知。失败、超时或任务结束后停止进度通知。

「视频生成」页提供前往「文案与提示词」和「指令与菜单」的快捷入口；模板与指令仍在原分区编辑。三种视频模板分别控制**开始、进度、完成**消息，留空使用内置文案，不影响图片文案。视频专用变量如下：

| 变量 | 含义 |
| --- | --- |
| `{prompt}` | 视频描述 |
| `{model}` / `{seconds}` | 视频模型 / 用户选择的成片时长（秒） |
| `{elapsed}` | 已等待时间（秒） |
| `{progress}` / `{progress_type}` | 百分比 / 实际或估算进度标签 |
| `{status}` / `{task_id}` | 当前任务状态 / 网关任务 ID |

进度模板建议保留 `{progress_type}`，便于区分真实与估算。完整提示词可能很长，编辑文案时需考虑聊天平台的消息长度限制。

提交 POST 不会自动重试，避免连接超时时重复创建计费任务。状态查询遇到暂时性网络故障、429 或 5xx 最多连续重试两次；第三次失败后停止等待并提示任务 ID。超时、插件重载或卸载仅停止本地等待，不代表已取消上游生成，也不会重新提交。任务不在重启后自动恢复；已有任务可凭任务 ID 在供应商处查询。视频内容下载上限为 100 MiB，临时文件在投递结束后清理。

## Scalar Web API

AstrBot Scalar 是部署实例提供的 OpenAPI 浏览器。打开 AstrBot 的 `/scalar.html` 后，页面会读取 `/openapi.json`；搜索 `astrbot_plugin_gpt_image` 即可查看当前插件已注册的接口、请求方法和响应定义。Scalar 页面显示的是运行中的实际版本，优先级高于本文中的示例。

插件接口前缀为 `/astrbot_plugin_gpt_image`：

| 方法 | 路径 | 用途 | 请求说明 |
| --- | --- | --- | --- |
| `GET` / `POST` | `/config` | 读取或合并保存插件配置 | `POST` 使用 JSON 对象；密钥只接受保存，不在响应中回显明文 |
| `GET` | `/suppliers` | 获取供应商及协议模型配置 | 返回脱敏后的供应商信息，并兼容 `suppliers`、`providers`、`channels` |
| `POST` | `/suppliers/test` | 测试供应商连通性 | JSON 指定供应商、协议或地址等测试参数 |
| `GET` | `/suppliers/model-check` | 按模型 ID 检测指定供应商目录 | 参数 `supplier`、`protocol`、`model`、`purpose=generate或edit`；`refresh=1` 刷新近期缓存。只读目录，不生成图片 |
| `GET` / `POST` | `/suppliers/diagnose` | 分阶段诊断供应商 | 检查 URL、鉴权、协议和模型目录；`/diagnostic` 为兼容别名 |
| `GET` | `/protocols` | 获取协议选项 | 无请求体 |
| `GET` | `/models` | 获取模型目录 | 支持供应商、协议、用途、分页和刷新参数；失败时查看响应错误 |
| `GET` | `/status` | 获取当前运行状态 | 返回版本、当前供应商、协议、模型、尺寸和基础统计 |
| `GET` | `/update-check` | 检查版本及构建修订 | 返回更新说明、可用更新与宿主支持情况 |
| `POST` | `/update-install` | 安装更新并重载 | 空 JSON `{}`；只操作本插件固定仓库，返回后台任务编号 |
| `POST` | `/plugin-reload` | 重载本插件 | 空 JSON `{}`；先确认插件注册身份与空闲状态 |
| `GET` | `/update-status` | 查询维护任务 | `job_id` 指定任务；新实例完成初始化验证后才返回 `succeeded` |
| `GET` | `/stats` | 获取会话统计 | 返回 `status_counts`、`session_totals`、`recent_sessions` 等字段 |
| `GET` | `/recent` | 获取最近交互对象 | 返回插件已见过的用户和群，供设置页一键选择 |
| `GET` | `/sizes` | 获取尺寸列表 | 无请求体 |
| `POST` | `/sizes/add` | 添加尺寸 | JSON：`{"size":"1024x1024"}` |
| `POST` | `/sizes/delete` | 删除尺寸 | JSON：`{"size":"1024x1024"}` |

### API 使用约定

- API 由 AstrBot 的 `register_web_api` 注册；若当前 AstrBot 未提供该能力，插件会跳过注册，聊天功能不因此失效。
- 具体鉴权、跨域、错误包装和 OpenAPI 展示方式由 AstrBot 宿主版本决定，插件不在文档中伪造固定的 HTTP 状态码或鉴权头。
- 保存供应商后再获取模型：模型目录按供应商和协议隔离，文本、视觉和绘画用途分别请求；完整目录不代表每个模型都具备对应能力。
- API Key、代理凭据等敏感字段只显示脱敏结果。不要把 Scalar 页面截图、响应内容或配置文件公开到不可信位置。
- `GET /stats` 的统计单位是会话，不是单次 HTTP 请求；批量任务和重试会在最终会话结算时去重。

## 八种协议与地址

| 协议 | 默认生成模型 | 地址与实现 |
| --- | --- | --- |
| `openai` | `gpt-image-2` | OpenAI 兼容图片接口；如 `https://api.example.com`，按需补 `/v1` |
| `gemini` | `gemini-2.5-flash-image` | Gemini `generateContent`；如 `https://generativelanguage.googleapis.com`，按需补 `/v1beta` |
| `grok` | `grok-2-image` | 图片接口及聊天接口回退；如 `https://api.x.ai`，按需补 `/v1` |
| `flux` | `flux-1.1-pro` | OpenAI 风格的 Flux 中转接口，按需补 `/v1` |
| `sdwebui` | 空字符串 | 如 `http://127.0.0.1:7860`；请求 `/sdapi/v1/txt2img` 或 `img2img` |
| `comfyui` | 空字符串 | 如 `http://127.0.0.1:8188`；提交 `/prompt` 工作流，默认使用文生图工作流，需选择已安装的 checkpoint |
| `jimeng` | `jimeng-3.0` | 即梦兼容网关，优先请求 `/api/v1/images/generations`，可处理同步结果或轮询任务 |
| `tongyi` | `wanx2.1-t2i-turbo` | 如 `https://dashscope.aliyuncs.com`；请求 `/api/v1/services/aigc/text2image/image-synthesis` 并轮询任务 |

中转协议地址已有版本段时不重复补版本；SD WebUI、ComfyUI 不自动补 `/v1`，即梦和通义万相由适配器拼接各自路径。使用服务根地址或服务商要求的前缀，避免把某个操作的完整 URL 当作所有操作共用的 Base URL。

新增的 Flux、SD WebUI、ComfyUI、即梦、通义万相协议仅经过本地 mock 验证，未做线上实测。图片编辑、多图输入及模型列表的可用性取决于协议实现和目标服务，默认 ComfyUI 工作流仅用于文生图。

## 绘画、编辑与批量

默认指令可在设置中修改。

| 用法 | 示例 |
| --- | --- |
| 文生图 | `绘画 广州塔宣传图` 或 `画图 一只猫` |
| 图片编辑 | `图片编辑 把背景换成夜景 https://example.com/a.png` |
| 同消息附图或引用图片 | 附图或引用图片后发送 `编辑图片 加上电影感光影` |
| 多图编辑 | `图片编辑 融合两张图 https://example.com/a.png https://example.com/b.png` |
| OneBot v11 头像编辑 | `图片编辑 手办化 @某人` |
| 重画 | `重画` / `再来一张`，复用本会话上次请求 |

批量仅用于文生图：`绘画 4张 一只猫` 会按同一提示词逐次请求；也可以发送以下一条多行消息：

```text
绘画 一只猫
一只狗
一只兔子
```

至少两行各有两个字符时按行拆分；只有一条提示词时才按数量重复。数量必须带单位，例如 `4张` 或 `x4张`，单独 `x4` 不表示批量。超出 `batch_max` 会提示并截取，默认上限 4，可设 1～10。图片编辑不拆分多行；绘画指令附图片链接时会尝试转为编辑。

`size_auto_detect` 仅在当前尺寸为 `auto` 时识别比例、分辨率等提示；识别后仍按协议尺寸规则处理，可能回落到可用尺寸。

## 权限与触发

- `trigger_mode=at`：OneBot 群聊需要 @机器人或唤醒前缀；`command` 模式允许以指令开头触发。QQ 官方机器人群聊在 `at` 模式下也允许免 @，前提是平台已投递该消息。私聊直接识别指令。
- `group_require_enable=true`（默认）：仅 `group_list` 中的群可使用普通指令；关闭该选项后，才按 `group_mode` 的 `all / whitelist / blacklist` 判断。主人用 `开群`、`关群` 或 `群开关 开/关` 管理本群。
- `我的ID`、`群列表`、群开关等指令可绕过群/私聊开关，但仍受平台、实例范围与用户黑名单限制；管理操作仍检查主人权限。
- `masters` 中的用户是主人。启用 `masters_use_astrbot_admin` 时，AstrBot 管理员在群聊和私聊均具有主人权限；当前实现另有私聊管理员兜底，即使关闭该选项仍可在私聊管理。
- `enabled_platforms`、`enabled_bot_ids` 控制响应范围；`bot_overrides` 可按机器人实例指定供应商、协议、模型和尺寸。无需复制插件目录。

| 指令 | 权限与作用 |
| --- | --- |
| `菜单` / `帮助` / `使用说明` | 普通用户查看用法 |
| `模型列表` / `尺寸列表` / `协议列表` / `供应商列表` | 普通用户查看选项；`模型列表 刷新` 需主人 |
| `切换模型` / `切换尺寸` / `切换协议` / `切换供应商` | 主人操作，参数支持序号或名称 |
| `添加尺寸` / `删除尺寸`、`添加主人` / `删除主人` | 主人维护配置 |
| `运行统计` / `重载配置` / `重置设置` | 主人查看统计、重读配置或清空本会话覆盖 |
| `我的ID` / `群列表` | 查看用户、群及实例信息或群范围 |

切换默认作用于当前会话，群聊会话可能由群成员共享；末尾加 `全局` 可持久化全局默认，例如 `切换模型 1 全局`。

## 预设、菜单与可选功能

- `预设列表` 查看内置提示词，`预设 赛博朋克` 或 `预设 1` 按名称/序号出图。预设走文生图流程，直接附图或引用不会自动转为编辑；需要参考图时，可把预设正文用于图片编辑指令。
- 主人可用 `添加预设 赛博猫 一只赛博朋克风格的猫`、`删除预设 赛博猫` 管理预设。
- `菜单列表` 查看分组；直接发送分组名 `模型与接口`，或发送 `菜单 模型与接口` 查看该分组。主人用 `设置菜单 模型功能 模型列表|协议列表`、`删除菜单 模型功能` 管理。分组入口同样遵守群开关、平台范围及主人权限规则，自定义菜单文案可用 `{分组菜单}` 插入分组内容。
- `prompts`、`menu_sections` 默认分别包含内置的 14 条预设和 6 个菜单分组。显式空列表表示清空，只有未配置或值为 `null` 时配置层才回落内置库；更新 schema 不会覆盖已保存的空列表。
- `抽卡` 每人每天一次，`排行` 查看本周出图张数；分别由 `gacha_enabled`、`rank_enabled` 控制。`flavor_enabled` 控制随机完成文案；`gacha_styles`、`flavor_lines` 为空时使用内置内容。
- 提示词翻译与 `图片转提示词` 默认关闭。在「⑦ 智能与玩法」中分别获取并选择翻译模型、视觉模型，也可以手动填写模型名；完整候选列表不代表每个模型都支持文本或视觉用途，请按供应商能力选择并保存。

## 文案变量

开始文案、完成文案、随机完成文案和菜单文案使用 `{变量名}`。变量取自本次事件和请求阶段；以下表格列出常用英文 key 与中文别名。未知变量，以及无法从已提供字段取得值的变量，原样保留，例如 `{未定义变量}`；显式传入空字符串或 `None` 才显示为空。兼容别名可复用已提供的值，例如 `{当前模型}` 可读取 `model`，但缺少上下文时不会编造用户、群、尺寸或提示词等信息。

变量值只替换一次：若原始消息里含有 `{模型}`，插入 `{原始消息}` 后仍保留这段原文。模板中写 `{{模型}}` 可显示字面量 `{模型}`。这些变量用于回复文案，不会在用户的画面描述中执行模板替换。

| 规范 key | 中文写法 / 别名 | 可用阶段 | 含义 |
| --- | --- | --- | --- |
| `original_prompt` | `raw_prompt`、`原始提示词` | 开始、完成 | 解析指令后、翻译或加工前的真正画面描述；不是包含指令的整条消息 |
| `final_prompt` | `最终提示词` | 完成时有内容 | 翻译或加工后提交给图片协议的内容；开始文案中为空 |
| `prompt` | `提示词` | 开始、完成 | 本次主要提示词；开始取首条计划描述，完成取首条成功请求的描述 |
| `mode` | `模式` | 开始、完成 | `draw`（绘画）或 `edit`（编辑） |
| `model` | `模型` | 开始、完成、菜单 | 请求使用的模型；菜单中为当前配置模型 |
| `size` | `尺寸` | 开始、完成、菜单 | 本次请求尺寸；菜单中为当前配置尺寸，不保证等于服务端最终返回图片的像素尺寸 |
| `width` / `height` | `宽度` / `高度` | 开始、完成、菜单 | 从实际尺寸取得的宽、高；尺寸为 `auto` 或无法解析时为空 |
| `count` | `数量` | 开始、完成 | 开始文案为计划出图数，完成文案为成功图片数 |
| `batch_count` | `batch`、`批量` | 开始、完成 | 本次请求数；数量前缀或多行提示词会增加请求数 |
| `input_count` | `输入图片数量`、`输入数量`、`输入图片数` | 开始、完成 | 输入素材图片数 |
| `failed_count` | `失败数量`、`失败数` | 完成 | 最终失败的请求数；与成功图片数分开统计 |
| `elapsed` | `耗时`、`用时` | 完成 | 总耗时，单位秒，数字格式保留两位小数 |
| `time` | `时间`、`当前时间`、`timestamp` | 公共上下文 | 构建上下文时的服务器本地时间，格式 `HH:MM:SS`；`timestamp` 是兼容别名，不是 Unix 时间戳 |
| `date` | `日期` | 公共上下文 | 同一上下文的本地日期，格式 `YYYY-MM-DD` |
| `datetime` | `date_time`、`日期时间`、`current_datetime` | 公共上下文 | 由 `date` 和 `time` 合并得到，格式 `YYYY-MM-DD HH:MM:SS` |
| `user` | `用户`、`昵称` | 公共上下文 | 发送者昵称 |
| `user_id` | `用户ID`、`用户编号` | 公共上下文 | 发送者 ID |
| `group_id` | `群ID`、`群号` | 公共上下文 | OneBot 群号或 QQ 官方机器人的 `group_openid`；私聊为空 |
| `group_name` | `群名`、`群名称` | 公共上下文 | 群名称；平台未提供时为空 |
| `platform` | `平台`、`平台类型`、`适配器` | 公共上下文 | 平台适配器名称，例如 `aiocqhttp`；不是机器人实例 ID |
| `bot_instance` | `机器人实例ID`、`bot_instance_id`、`bot_id`、`platform_id` | 公共上下文 | AstrBot 中的机器人实例 ID，用于区分同平台的多个机器人 |
| `supplier` | `供应商` | 开始、完成、菜单 | 本次使用或菜单当前选中的供应商 |
| `protocol` | `协议` | 开始、完成、菜单 | 兼容旧模板；中文 `{协议}` 可为显示名，英文 `{protocol}` 可为内部 key，精确区分时使用以下专用变量 |
| `protocol_key` | `协议键` | 开始、完成、菜单 | 协议内部 key，例如 `openai` |
| `protocol_label` | `协议名称`、`协议显示名` | 开始、完成、菜单 | 协议显示名，例如 `OpenAI 兼容` |
| `message_id` | `消息ID` | 公共上下文 | 原平台消息 ID；平台未提供时为空 |
| `session_id` | `会话ID` | 公共上下文 | 当前会话的统一消息来源标识 |
| `raw_message` | `原始消息`、`原始文本` | 公共上下文 | 平台事件提供的原始消息文本，可含指令、链接和换行 |
| `timeout` | `超时` | 开始、完成、菜单 | 配置的接口超时秒数 |
| `batch_index` | `batch_position`、`request_index`、`批量位置` | 开始、完成 | 当前批量请求位置，从 1 开始；没有批量上下文时为空或未提供 |
| `aspect_ratio` | `ratio`、`画面比例` | 开始、完成、菜单 | 从有效宽高约分得到的比例，例如 `16:9`；`auto` 尺寸时为空 |
| `pixel_count` | `pixels`、`像素数` | 开始、完成 | 从有效宽高计算得到的总像素数；无法解析尺寸时不提供 |
| `is_square` | `是否正方形` | 开始、完成 | 宽高相等时为“是”，否则为“否”；无法解析尺寸时不提供 |
| `is_batch` | `是否批量` | 开始、完成、菜单 | 请求数量大于 1 时为“是”，否则为“否” |
| `has_success` | `是否有成功` | 完成 | 成功数量大于 0 时为“是”，否则为“否” |
| `has_failure` | `是否有失败` | 完成 | 失败数量大于 0 时为“是”，否则为“否” |
| `current_model` / `current_size` | `当前模型` / `当前尺寸` | 菜单 | 当前配置模型和尺寸 |
| `menu_sections` | `分组菜单` | 菜单 | 配置的菜单分组内容 |

“公共上下文”可用于开始、完成及菜单文案；菜单只接收允许的上下文字段，不代表菜单拥有绘画任务的结果。菜单中没有本次请求时，不提供 `final_prompt`、`elapsed` 或成功数量等结果变量。

完整日期时间使用 `{日期} {时间}`，例如 `2026-09-12 12:34:56`；不要把 `{timestamp}` 当作日期时间或 Unix 时间戳。`{日期时间}` 未单独定义时会原样保留。

`count`、`batch_count`、`input_count`、`failed_count` 分别表示图片数量、请求数量、输入素材数量和失败请求数量，不能互相替代。例如计划 4 次请求且没有输入素材时，开始的 `count=4`、`batch_count=4`、`input_count=0`；若其中一次失败、其余各返回一张图片，完成时 `count=3`、`failed_count=1`，`batch_count` 仍为 4。

新增派生变量只根据已经传入的上下文计算，不会访问网络、读取隐私数据或改变原变量。`datetime` 需要同时存在 `date` 与 `time`；`aspect_ratio`、`pixel_count` 和 `is_square` 需要可解析的 `width`、`height`；`is_batch`、`has_success` 和 `has_failure` 缺少数量时按 0 计算。调用方若显式传入同名变量，显式值优先。

`original_prompt` 是画面描述，`raw_message` 是整条原始消息，`final_prompt` 只在完成阶段反映最终提交内容。开始文案传入的 `final_prompt` 为空，不用原始提示词冒充最终内容；若某个调用场景完全未传入该字段，占位符会原样保留。批量完成文案的提示词和尺寸取首条成功请求，数量与耗时则汇总整批任务。`auto` 尺寸的 `width`、`height` 显式为空，不推测宽高。

开始文案例子：`准备生成 {数量} 张图片：{原始提示词}`。完成文案例子：`成功 {数量} 张，失败 {失败数量} 次，耗时 {耗时} 秒；提交内容：{最终提示词}`。

## 本轮修复使用说明

- **单页工作台设置**：概览、供应商与协议、模型与尺寸、视频生成、指令与菜单、文案与提示词、权限与范围、智能与玩法、使用说明集中在同一页面，通过左侧锚点导航快速定位；修改后点击顶部「保存配置」，滚动或跳转不等于保存。界面支持亮色/暗色主题，并为后续主题扩展保留 `data-theme` 钩子。
- **翻译/视觉模型获取**：先保存供应商的 Base URL 和 API Key，再到「⑦ 智能与玩法」，在翻译模型或视觉模型旁点击「获取完整模型列表」。翻译使用所选翻译供应商（留空沿用绘画供应商），视觉使用当前绘画供应商；点击候选可填入对应输入框，也可手动填写，最后保存。候选来自服务端，是否支持翻译或视觉输入由服务商决定；不要仅凭出现在列表中就认为模型具备该能力。聊天中的绘画模型列表优先用缓存，无缓存时尝试联网，主人可用 `模型列表 刷新` 强制重拉。
- **旧供应商迁移**：重载时读取旧版 `providers` / `channels`、`active_provider`，迁移供应商地址、密钥及协议模型。框架注入的空默认供应商不应遮蔽已有旧配置；已有真实的新供应商配置时优先保留新配置。迁移后到「② 供应商与协议」核对当前供应商，再测试连接。
- **复制降级**：点击设置页中的可复制文本；浏览器剪贴板不可用或权限被拒绝时会尝试兼容复制，仍失败则弹出已选中文本的手动复制框，使用 `Ctrl+C` 或系统复制菜单。只有实际复制成功才提示成功；出现手动复制框不表示剪贴板已经写入。
- **分组入口**：`菜单列表` 查分组名，直接发送 `模型与接口`，或发送 `菜单 模型与接口` / `菜单模型与接口` 打开同一分组（即「分组名」和「菜单分组名」形式，前缀后可有空格）。群聊仍需满足当前唤醒方式和群权限要求；分组名称本身不授予主人权限。

当前版本为 `1.0.10`。

## 排查

无响应时依次检查消息是否触发、平台/实例范围、黑名单及群是否开启。OneBot 群 ID 为群号，QQ 官方机器人使用 `group_openid`，可在目标群发送 `我的ID` 获取。

接口失败时检查 Base URL、密钥、协议及模型是否匹配；本地服务地址应能从 AstrBot 所在环境访问。默认接口超时 `timeout=600` 秒，日志关键字为 `[gpt-image]`。
